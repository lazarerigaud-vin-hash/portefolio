L'entreprise — Groupama Centre-Atlantique

Groupama dans le monde

Groupama Assurances Mutuelles est un groupe mutualiste présent dans 10 pays, dont l'activité se répartit entre l'assurance, les services financiers et l'épargne. Le groupe exploite deux marques commerciales : Groupama, la marque généraliste distribuée en France par le réseau de caisses régionales, et Gan, la marque orientée expertise client avec un suivi personnalisé.

Groupama en France

En France, le groupe s'appuie sur un réseau de près de 3 000 agences, avec 30 000 élus bénévoles et 25 000 collaborateurs. Pour assurer une proximité territoriale maximale, le maillage régional comprend 9 caisses régionales métropolitaines, 2 caisses d'outre-mer et 2 caisses spécialisées (Forêts, Producteurs de tabac).

Groupama Supports & Services

Le GIE national Groupama Supports & Services fournit des services informatiques à toutes les entreprises du groupe. Il est responsable des systèmes d'information, de la logistique et des achats de matériel informatique pour l'ensemble des caisses régionales.

GCA est une caisse régionale à but non lucratif : les excédents servent à améliorer les remboursements, diminuer les tarifs ou assurer de nouveaux risques, sans rémunérer d'actionnaires. Les sociétaires élisent leurs représentants, qui participent à la gouvernance locale et régionale.

Organisation interne

GCA est structurée autour de huit grandes directions : le développement commercial, la souscription, la santé-prévoyance, le courtage, le système d'information (DSI), technique et indemnisation, les finances et logistique, et le secrétariat général.

Service d'accueil — Équipe de développement

Mon service d'accueil est le service de développement section nord, rattaché à la DSI de GCA. La DSI comprend des équipes dédiées au pilotage de projets, à la gestion courante du SI, au support utilisateur, à la data et au pilotage, ainsi qu'à l'innovation et aux solutions numériques.

Mission du service

Le service assure l'assistance, le support technique et la gestion des demandes ou incidents pour les utilisateurs internes (aussi appelé SVP — Service de support technique). Il garantit le bon fonctionnement des outils informatiques, gère les incidents techniques, maintient les systèmes d'information et accompagne les utilisateurs dans l'utilisation des outils internes (GED, iSi, RECRE, etc.).

📋 Les utilisateurs peuvent rapporter un incident ou soumettre une demande ASR (Automatisation des Services et Ressources) via le portail ServiceNow.

Réalisation technique

Difficultés de la première semaine

Au début du stage, j'ai eu des difficultés à comprendre l'expression de besoin : le document était dense et le vocabulaire parfois technique m'était peu familier. De plus, je ne maîtrisais pas encore suffisamment Visual Studio, ce qui m'a freiné dans la mise en place des premières étapes. J'ai passé plusieurs heures à revoir certaines notions fondamentales.

Stratégie de la deuxième semaine

Pour limiter la complexité, j'ai décidé de me concentrer sur un cas d'utilisation précis : l'affichage d'une liste de demandes. L'objectif était de créer une table SQL, de la connecter à l'application ASP.NET et d'afficher dynamiquement les données dans une page web.

Étape 1 — Tentative avec Visual Studio

J'ai d'abord tenté de créer la table SQL directement depuis Visual Studio via un script SQL. Cette approche a rencontré des erreurs de connexion et de configuration du serveur SQL local, que je n'ai pas réussi à résoudre.

-- Script SQL testé dans Visual Studio CREATE TABLE Demande ( Id INT PRIMARY KEY IDENTITY, Nom NVARCHAR(255), Description NVARCHAR(MAX), TypeDemande NVARCHAR(100), Demandeur NVARCHAR(255), Direction NVARCHAR(100), DateSouhaitee DATETIME, Statut NVARCHAR(100) );

Étape 2 — Installation de SQL Server Management Studio

Face aux difficultés, j'ai opté pour l'installation de SQL Server et SQL Server Management Studio (SSMS). J'ai créé la table Demandes directement dans SSMS (via l'interface graphique et via requête SQL), avec les champs : Id, NomDemande, Description, DateDemande, Etat, Direction.

Étape 3 — Modèle C# et vue Razor

Pour afficher les données, j'ai créé un modèle Demande.cs représentant une ligne de la table, puis une page Razor Pages pour l'affichage dynamique. J'ai utilisé une boucle foreach pour parcourir les demandes et les afficher en HTML.

Étape 4 — Connexion Entity Framework

J'ai configuré la connexion entre la base de données et l'application dans le fichier Program.cs :

// Program.cs — configuration de la BDD using Microsoft.EntityFrameworkCore; builder.Services.AddDbContext<MonContexte>(options => options.UseSqlServer( builder.Configuration.GetConnectionString("MaConnexion") ) );

Résultat

✅ J'ai réussi à créer une page web fonctionnelle affichant dynamiquement les demandes depuis la base de données SQL Server, via Entity Framework et ASP.NET Razor Pages.

Bilan & Conclusion

Bilan du projet

Le cahier des charges était ambitieux pour la durée du stage. Cependant, j'ai réussi à implémenter une partie fonctionnelle de l'application : création de la base de données, connexion ORM, affichage dynamique des demandes. J'ai acquis une vision claire du cycle de développement d'une application web professionnelle.

Ce que j'ai appris

  • Créer et connecter une base de données SQL Server à une application C#
  • Utiliser Entity Framework Core comme ORM
  • Développer une interface avec ASP.NET Razor Pages
  • Lire et interpréter une expression de besoin et un cahier des charges
  • S'intégrer dans une équipe professionnelle de développement
  • Décomposer un problème complexe en tâches progressives
